Kaggriculture agent · improvement loop · Aug – Sep 2026

From autopilot to a gated loop

The system that improves my Kaggle simulation agent started fully autonomous so I could move fast. Measuring what it cost changed the design: the machine now watches, and a person decides when to spend.

Where it started · Aug 11 – 17

The autonomous loop

no human anywhere in the cycle

What one cycle did

  • Every 4 hours: download new games from Kaggle
  • An LLM with write access studied them and rewrote the agent itself
  • It benchmarked the change against its own previous version
  • On a pass: submitted to Kaggle and pushed to GitHub, unreviewed

What it cost

  • Codex hit the OpenAI spend cap on day 2; swapped to Claude Opus
  • 23 runs, ~59 hours of high-effort sessions in one week
  • Memory file re-read in full every run, growing 6× in six days
  • After day 4: eleven runs in a row shipped nothing

Why it was worth it

  • Six versions shipped without me touching them
  • Running it is how I found what needed a gate
  • The hidden risks: it edited code under my own session, and benchmarked against a misconfigured simulator

Where it ended · Aug 19 onward

A watcher plus human gates

automation watches · you decide when to spend

What changed

  • The schedule only watches: download games, build a ≤ 20 KB evidence packet, notify
  • Claude runs only when armed: Sonnet, read-only, 6 turns, ≤ 80 KB of input, one patch or “wait”
  • The evaluator matches the real competition and was checked against past versions before it was trusted
  • Applying a patch, and submitting it, are separate commands; any failure restores the baseline

How it behaved

  • The planner mostly answered “wait” — the cheap, correct answer when nothing new justified a change
  • The gate blocked a change that passed a 4-seed screen but lost money on 2 of 12 seeds
  • Everything is in ARCHITECTURE.md and automation.ps1

Start with maximum automation to learn fast. Then automate the watching, and keep the spending decisions human.
